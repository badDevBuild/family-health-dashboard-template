# 隐私与发布门禁

健康数据具有高度敏感性。这个模板的默认规则是：真实数据可以参与本地处理，但永远不进入 Git 历史。

## 绝不提交

- 原始 PDF、图片、DICOM、压缩包和报告导出。
- 真实姓名、头像、生日、证件号、电话、就诊号和精确地址。
- `data/`、`reports/`、`src/lib/health-data.private.ts` 与真实构建产物。
- PIN 明文、哈希、Cookie 密钥、云端凭据、私钥和部署主机路径。
- 模型复核的原始输入、响应和日志，除非内容完全为虚构数据。

## 发布前检查

1. 从白名单文件创建新仓库，不复制原仓库 `.git/`。
2. 用虚构人物和虚构机构替换所有测试夹具。
3. 在 `privacy-denylist.local.txt` 中加入项目相关真实标识。
4. 运行 `npm run privacy-check`，再用 `git grep` 和 secret scanner 复核。
5. 检查 Git 历史；新模板应只有脱敏后的提交。
6. 在 GitHub 创建仓库后读回文件树和可见性，确认没有意外公开。

## 已经误提交怎么办

立即把仓库设为私有、轮换所有凭据，并按 GitHub 官方流程清理历史。仅删除当前文件不够，因为旧提交仍可访问。涉及真实健康资料时，还应评估通知和合规义务。

## 第三方模型

把健康数据发给第二模型、OCR 或云服务属于外部传输。调用前要说明处理方、发送范围、用途、保留风险和重复上传策略，并获得对应授权。复核成功只证明传输和返回结果可用，不自动证明医学内容正确。
